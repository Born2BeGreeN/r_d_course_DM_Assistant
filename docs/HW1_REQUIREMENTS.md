# HW1: Structured Extraction Service

Проєкт: Adventure Assistant — помічник Dungeon Master для вилучення фактів із документів пригод настільних RPG. Цей документ фіксує цільовий обсяг; наявність пункту не означає його реалізацію.

## Обов'язкові вимоги домашнього завдання

- Щонайменше 30 різноманітних сирих текстів із реалістичними недосконалостями тексту та пропущеною інформацією.
- Рівно 10 із цих текстів користувач вручну анотує як golden set. Асистент не вигадує та не підмінює ручні анотації.
- Схема містить щонайменше шість полів, enum і вкладений об'єкт або список.
- Одна модель через API провайдера зі structured output та одна локальна модель через спільний інтерфейс.
- Щонайменше дві sampling-конфігурації; `temperature` та `top_p` явно присутні в конфігурації.
- Щонайменше дві версії extraction-промпту та changelog змін.
- Таймаути, обмежена кількість повторних транспортних запитів, валідація за схемою та не більше однієї спроби виправлення невалідного результату; після невдалого виправлення результат позначається як failed.
- Метрики: field-level accuracy, відсоток валідних відповідей, latency p50/p95 та вартість на 1000 текстів.
- Порівняння моделей, промптів і sampling-конфігурацій; 3–5 фактичних прикладів помилок та обґрунтований вибір для production.
- Артефакти: код, промпти, тексти, golden labels, збережені результати, `REPORT.md`, `README.md`, `.env.example` та запуск однією командою після налаштування.
- Сукупний бюджет зовнішніх model API для цього домашнього завдання — не більше USD 5, включно з повторними запитами та виправленнями.

## Технічні рішення та обмеження реалізації

Це рішення для цього проєкту, а не додаткові вимоги курсу:

- Python 3.11+, бажано 3.12; `uv` для залежностей і запуску.
- Pydantic для схеми й валідації, `pypdf` для читання PDF, SDK обраного API-провайдера, Ollama для локальної моделі.
- Зберігати реалізацію невеликою. Конкретні моделі, поля схеми, числові значення sampling, таймаути, ліміти retries, правила обчислення метрик і команда запуску визначаються на наступних кроках.
- Вести облік сукупних витрат і перевіряти бюджет перед зовнішніми викликами. Не виконувати запит, якщо його можлива вартість перевищить залишок бюджету.
- Перевірки реалізації використовують mocks; живі зовнішні виклики дозволені лише на кроках, де користувач прямо їх просить.
- Зберігати походження текстів, оригінальні PDF, ручні мітки та історичні результати. Відсутні факти не домислювати.
- Реальні ключі зберігати поза Git і не виводити в чат чи логи; `.env.example` містить лише безпечні приклади або порожні значення.
